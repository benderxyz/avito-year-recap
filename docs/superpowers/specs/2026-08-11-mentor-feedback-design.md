## Замечание 1. Сравнение с другими пользователями

Ментор увидел строку «Это больше чем у 0% пользователей» и не понял, что она значит.

Проблем на самом деле две. Первая, перцентиль считается функцией `lowerPercentile`
в `analytics-service/internal/aggregation/percentile.go` как доля пользователей строго
ниже текущего, поэтому для новичка ноль это валидный результат, а не сбой. Вторая,
шаблон текста один на все метрики, и из него не видно, что именно сравнивается.

### Порог на метрику

Порог, ниже которого сравнение не показывается, задается данными, а не константой
в коде. В таблицу `metric_definitions` добавляется колонка.

```sql
ALTER TABLE metric_definitions
    ADD COLUMN IF NOT EXISTS comparison_min_percentile numeric;

ALTER TABLE metric_definitions ADD CONSTRAINT metric_definitions_comparison_min_percentile_check
    CHECK (comparison_min_percentile IS NULL
        OR (comparison_min_percentile >= 0 AND comparison_min_percentile <= 100));
```

Порог лежит на строке базовой метрики, например `listingsPublished`, а не на строке
перцентиля `listingsPercentile`. Так он оказывается рядом с колонкой `percentile_key`,
которую ограничивает, и совпадает с тем, как работает `attachPercentile`
в `cards-service/internal/cards/generator.go`. Функция резолвит определение метрики
по полю `value` сцены и только потом читает из него ключ перцентиля.

Значение `NULL` означает дефолт сервиса. Дефолт живет в пакете `cards` как константа
`defaultComparisonMinPercentile` со значением 50. Подстановка дефолта происходит
на загрузке правил в `RuleStore.loadMetricDefinitions`, чтобы в модели поле было
обычным `float64` и генератор не тащил проверки на nil.

В `models.MetricDefinition` добавляется поле `ComparisonMinPercentile float64`.
В запросе `loadMetricDefinitions` добавляется колонка, скан идет через
`sql.NullFloat64` с подстановкой дефолта при отсутствии значения.

Условие показа сравнения в `attachPercentile` становится таким.

```go
if percentileValue <= 0 || percentileValue < def.ComparisonMinPercentile {
    return scene
}
```

Ноль отсекается всегда, независимо от порога. Даже если в базе кто-то выставит
порог 0, строка про ноль процентов не вернется. Это ровно тот случай, который
увидел ментор.

Когда сравнение не проходит порог, ключ `percentile` в сцену не кладется. Движок
рисует блок сравнения только при наличии этого ключа, поэтому карточка выводится
без строки сравнения и ничего дополнительно на фронте отключать не нужно.

В сидах всем пяти метрикам с перцентилем ставится 50. Дальше значение крутится
через SQL без релиза сервиса, как и остальные пороги правил.

### Тексты сравнений

Шаблон становится пометричным. Поле `comparisonTemplate` в payload правила уже
поддерживается, `attachPercentile` подставляет свой текст только когда в правиле
своего нет.

| Правило | Текст |
| --- | --- |
| stat-listings | Объявлений у вас больше, чем у {{percentile}}% продавцов |
| stat-views | Ваши объявления смотрели чаще, чем у {{percentile}}% продавцов |
| stat-favorites | В избранное вас добавляли чаще, чем у {{percentile}}% продавцов |
| stat-deals | Сделок больше, чем у {{percentile}}% продавцов |
| stat-messages | Вы переписывались активнее, чем {{percentile}}% пользователей |

Дефолтный текст в Go остается запасным вариантом и переформулируется в
«Больше, чем у {{percentile}}% пользователей Авито».

### Что не трогаем

Пакеты `recap-engine` не меняются. Фронтенд подключает `@recap-engine/core`
и `@recap-engine/react` как опубликованные npm-пакеты с фиксированными версиями,
установлена версия ядра 1.2.0. Правка исходников движка в приложение не попадет
до релиза пакета. Дефолтные шаблоны сравнения внутри ядра в любом случае
перекрываются бэкендом, так что менять их незачем.

## Замечание 4. Кругозор

Ментор не понял, что значит «Вы попробовали XXX категорий». Посмотрел, купил,
продал.

Метрика `categoriesTried` собирается из событий `category_opened` с уникальностью
по `payload.category`, смотри `analytics-service/seeds/001_event_registry.sql`.
То есть это категории, которые пользователь открывал в поиске, а не те, где он
что-то продал. Слово «попробовали» вводит в заблуждение.

Правило `stat-categories` переводится из типа `stat` в тип `blocks` по образцу
`blocks-search` и `blocks-days-active`, чтобы под цифрой поместился поясняющий
callout.

```
Кругозор
   9
категорий
вы открывали за год

Заглядывали в разные разделы, от электроники до садовой мебели
```

Аналитика не меняется. Метрика как считалась по уникальным `category_opened`,
так и считается, меняется только текст.

`docker compose up --build`, залить данные через `seed-data/seed-script`, пройти

в проект не нужно, для разовой съемки хватит `npx playwright`. Готовые PNG кладутся
в `docs/static/readme/`.

## Раскатка

Сиды вставляют правила через `ON CONFLICT (id) DO NOTHING`, поэтому правка текстов
в `001_rules.sql` на существующей базе сама по себе не применится. Тексты правятся
в двух местах. Сид нужен для чистой базы, миграция для существующей.

Миграции разделяются, чтобы схема и контент не смешивались.

- `cards-service/migrations/007_metric_comparison_threshold.sql`, колонка,
  constraint, значения 50 для пяти метрик с перцентилем
- `cards-service/migrations/008_recap_content_v2.sql`, пять пометричных
  `comparisonTemplate`, перевод `stat-categories` в `blocks`, удаление строки
  `sellerRating` из `metric_definitions`

Реестр событий `analytics-service` живет в Postgres, схема в
`analytics-service/migrations-pg/001_event_registry.sql`, данные в
`analytics-service/seeds/001_event_registry.sql`. Строка `seller_rating` удаляется
из сида и отдельной миграцией `002_drop_seller_rating.sql` в той же папке
`migrations-pg`. Папка `migrations` относится к ClickHouse и не затрагивается.

## Тесты

- `attachPercentile`, сравнение прикрепляется при перцентиле выше порога
- `attachPercentile`, сравнение не прикрепляется при перцентиле ниже порога
- `attachPercentile`, сравнение не прикрепляется при перцентиле 0 и пороге 0
- `attachPercentile`, пометричный `comparisonTemplate` из правила не перетирается
  дефолтным
- `loadMetricDefinitions`, при `NULL` в колонке подставляется дефолт 50
- существующие тесты, где фигурирует `sellerRating`, чистятся от ключа
