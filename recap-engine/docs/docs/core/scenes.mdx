# Сцены

**Сцена** — один полноэкранный шаг recap: приветствие, число, текст, бейдж, финал.

Если вы **не используете backend**, сцены описываете массивом в коде. Функция `defineScenes` принимает этот массив и проверяет, что у каждой сцены уникальный `id`.

## Минимальный пример

```tsx
import { defineScenes, ESceneType } from '@recap-engine/core';

const scenes = defineScenes([
  {
    id: 'intro',
    type: ESceneType.Intro,
    title: 'Привет!',
  },
  {
    id: 'stat',
    type: ESceneType.Stat,
    title: 'Объявлений',
    value: 42,
    unit: 'шт.',
  },
  {
    id: 'outro',
    type: ESceneType.Outro,
    title: 'До встречи!',
  },
]);
```

Порядок элементов в массиве = порядок экранов при листании.

## Статические и динамические значения

Поля сцены (заголовок, число, текст) могут быть:

**Строкой или числом** — одинаково для всех:

```tsx
title: 'Ваш год',
value: 42,
```

**Функцией от data** — подставляет значения из ваших данных:

```tsx
title: ({ data }) => `${data.userName}, ваш год`,
value: ({ data }) => data.publishedAds,
```

Функция получает **контекст** — объект с полями:

```ts
{
  data,    // ваш объект data из <Recap>
  theme,   // текущая тема
  index,   // номер текущей сцены (0, 1, 2…)
  total,   // всего сцен
  format,  // форматтеры чисел и валют
}
```

Так stat-сцена может показать разное число для каждого пользователя, не меняя описание сцены.

## Общие поля любой сцены

| Поле | Зачем |
|------|-------|
| `id` | Уникальное имя (навигация, `initialSceneId`, аналитика) |
| `type` | Вид экрана — `Intro`, `Stat`, `Insight`, … |
| `background` | Фон: цвет, градиент, картинка |
| `motion` | Анимация перехода на/с этого экрана |
| `durationMs` | Сколько держать экран при autoplay |
| `actions` | Кнопки внизу (Поделиться, Далее, Закрыть) |

Поля для каждого `type` — в [Типах сцен](./scene-types).

## defineScenes

```ts
const scenes = defineScenes<MyData>([...]);
```

- Возвращает типизированный массив `SceneDefinition<MyData>[]`.
- Если два экрана с одинаковым `id` — ошибка при инициализации.
